# V0.1.1 operational handoff

## Lean private runtime choice

Keep the existing Python/SQLite application. No framework, database service,
auth provider or platform rewrite is needed for one owner. The database requires
a persistent private local filesystem and one authoritative coordinator; do not
run independent clones with separate request ledgers against the same sources.

| Option | Cost and sustainability | Decision |
|---|---|---|
| Existing owner computer, loopback, on demand | No new provider subscription, resource or account. Existing hardware/power availability is not verified. Available while the owner runs it; remote devices need a separately reviewed private connectivity path. | Leanest ongoing single-person option, conditional on available hardware. No configuration performed. |
| Existing Codespace, private port, owner session only | Reuses current infrastructure and code. Included compute/storage are finite; actual remaining allowance and billing controls were not audited. A stopped Codespace still consumes storage. | Best immediate private validation option; no zero-cost or always-on hosting promise. No port visibility or account settings changed. |
| New hosted service / serverless rewrite | Account, persistent storage, private access and pricing need separate approval. Rewrite and operational burden with no demonstrated benefit for this slice. | Defer; neither provisioned nor recommended as necessary now. |

GitHub confirms [private forwarding requires creator authentication](https://docs.github.com/en/codespaces/reference/security-in-github-codespaces),
[compute/storage consume finite included usage](https://docs.github.com/en/codespaces/troubleshooting/troubleshooting-included-usage),
and [stopped Codespaces still incur storage usage](https://docs.github.com/en/codespaces/about-codespaces/understanding-the-codespace-lifecycle).
Reviewed 2026-11-25. Existing machine ownership or use of a free allowance does not
establish zero incremental billed cost. **No sustainable always-on zero-cost
host was established.** Do not add payment details, raise budgets, keep an idle
Codespace running for hosting or change account settings under this task.

## Live reader setup boundary

Default remains synthetic. The [policy](./V0.1.1_SOURCE_POLICY.md) allows a new
private live store, independent of synthetic fixtures and the compatibility ledger:

```sh
python3 -m pilot.app init --data .local/private-reader.sqlite3 --mode live
python3 -m pilot.app serve --data .local/private-reader.sqlite3 --port 8766
```

These are operator instructions, not evidence of an initialized real owner.
Choose the password privately at the interactive prompt; no default exists.
For forwarded validation follow [private HTTPS setup](../pilot/README.md).
No live-enable environment variable, arbitrary source URL, background poll or
backup override exists. Do not clone the runtime DB to another serving instance.
A new database is not a legitimate way to evade the per-owner request budget.

Stop serving before changing code. Preserve owner data; live data cannot be
backed up by the maintenance command. Recheck source policy before release.
Do not use V0.1 code with a V0.1.1 live store. New schema additions are local;
no hosting migration, service installation or rollback was executed.

## One consolidated owner-operated session

All unavailable physical-device and actual Codespaces identity checks should be
performed together, after reviewing [actual automated evidence](./V0.1.1_EVIDENCE.md).
Do not send credentials or actual preview URLs to chat or commit them. Record
only device/browser versions, UTC timestamps, viewport measurements and sanitized
pass/fail observations. Do not treat unchecked items as Pass.

1. In the existing Codespace, verify port 8766 is **Private** in Ports. Start the
   reviewed app with its exact copied HTTPS origin as described in setup. Do not
   make it public or change GitHub/account settings. Use synthetic mode first.
2. On the owner's desktop/Chromebook and Android browser, complete actual GitHub
   private-preview authentication and local owner login. Inspect cookie attributes
   (`__Host-pilot_session`, Secure, HttpOnly, Strict), verify anonymous data denial
   in a separate private browser context, and verify no CSP/console errors. A
   loopback headless browser is not evidence that this forwarding flow works.
3. In the same session, check Articles/Manage at desktop and 390×844 or physical
   mobile width: overflow, text/unknown/aggregate labels, keyboard focus, tap
   targets, original link/attribution, profile save/rematch/reload, manual vs
   foreground eligibility, no polling while idle. Check actual Chromebook/Android
   usability rather than claiming device acceptance from emulation.
4. Start an explicitly selected new live store only within the bounded policy.
   View the real aggregate cards without merchant navigation or screenshots
   containing live payloads. Manual/foreground repeat before 30 minutes must
   skip; a permitted later request must preserve budget/retention. Automated live
   evidence already recorded here need not be repeated merely to chase a Pass.
5. With browser network throttling, sign out during refresh and profile save;
   navigate back/forward and confirm no private view reappears. Simulate one
   failed logout: view clears immediately, warning/retry appears; restore network,
   retry and confirm session revoked. Sign in anew and check stale responses
   cannot clear or overwrite the new view. Repeat on the actual mobile browser.
6. Stop the temporary process; verify forwarding remains Private, close test tabs
   and remove only disposable test data. Do not delete the actual owner's profile
   or runtime files without their decision. Record one consolidated sanitized
   report with failed checks and release decision. No production deployment,
   merge, new source family or next-version work follows automatically.

Release also needs owner review of the private-reader interpretation and retention
limits, actual cost/host availability if remote hosting is wanted, and explicit
release/deployment authorization. No paid service, account or infrastructure was
created in preparation.
