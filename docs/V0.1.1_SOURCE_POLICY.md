# V0.1.1 private RSS reader policy — 2026-11-25

## Independently checked permission evidence

The current [Brickset RSS index](https://brickset.com/article/52663/index-of-rss-feeds)
explicitly invites keeping up to date in a favourite RSS reader and lists Amazon
Canada and USA. Both the indexed text and direct HTML were inspected on
2026-11-25. The old `/tools/rssindex` is an almost-empty shell linking to this
article; `/about/terms` and `/terms` returned Page not found. Those missing pages
are not evidence of permission. The [2021 reader announcement](https://brickset.com/article/57700/keeping-up-to-date)
supports ordinary RSS subscription. The [2024 rejected full-feed suggestion](https://brickset.com/suggestions/rejected)
explains the intent to direct readers back to the website. The
[privacy/cookies page](https://brickset.com/article/52660/privacy-and-cookies)
describes site visitor data and affiliate funding, not a feed reuse licence.
[Robots](https://brickset.com/robots.txt) does not disallow `/feed`; this is only
crawl guidance, not copyright permission. No API key or API reuse terms invoked.

**Decision:** an ordinary, single-person private RSS reader with a short-lived
metadata cache is a defensible interpretation of the explicit reader invitation.
This is an engineering interpretation, not express numerical terms, provider
approval, legal advice, a blanket structured-data licence or authorization to
redistribute. No separate affirmative retention licence was found. Broader use
remains outside scope. Stop live use if the invitation changes, the provider
objects or restrictive terms appear; recheck policy before release and expansion.
No provider contact or external account configuration was performed.

## Enforced operating boundary

- Only HTTPS `brickset.com/feed/amazon/ca` and `/us`; no article, merchant or
  enrichment fetch. No redirects, arbitrary destination or authenticated scraping.
- One local owner; foreground/open/manual checks only. At least **1,800 seconds**
  after completion per source, with longer exponential/Retry-After backoff.
  At most **8 attempts/source in a rolling 24 hours**, failures included, across
  restarts. Independent of bounded display-run history; skips do not erase budget.
  No scheduler, polling, forced refresh or interval reduction for acceptance.
- Persist at most **50 minimal article records/source**, source attribution,
  original canonical article link, title, ID, market, publication/observation
  dates and cache metadata. No feed bodies, descriptions, images, full text,
  individual offers, prices or historical snapshots. Existing optional unknown
  fields remain null. Article links lead back to Brickset without affiliate edits.
- Explicit HTTP `no-store` or `no-cache` refuses persistence and clears the old source baseline/validators. This conservative reader does not implement reuse that requires validation on every access.
- Rolling replacement, **two-hour logical retention** since last 200 observation;
  a 304 never extends content retention. Failure never extends last-good lifetime.
  Expired retained metadata is deleted on startup/read/refresh. No live backup or
  restore through the maintenance command. No live data in Git, evidence or logs.
- These numbers are deliberately conservative local safeguards, **not numbers
  supplied or guaranteed by Brickset**. Stopped processes do not physically erase
  files at deadline; SQLite/WAL/filesystem media may retain bytes. No forensic
  erasure guarantee. Delete disposable live-validation directories after review;
  do not copy runtime databases. A physical-erasure SLA requires separate design.
- Synthetic default remains; opt in using a **new** private `--mode live` database.
  Existing synthetic/live-blocked stores never silently change mode. Policy can
  revoke live use before network activity and before writing real metadata.

## Deferred permission boundaries

Public sharing, multi-user service, commercial reuse, full-text copies, live
archives/backups, historical pricing, arbitrary automation and merchant/offer
extraction have no permission established by this review. No such feature is
implemented. Slickdeals and GPT remain excluded. Release still requires actual
owner HTTPS/device checks and a current policy review; successful HTTP tests do
not grant source rights.
