## Runtime decision

Selected **Python standard library + SQLite for local development only**. One
backend serves the shell/assets and authenticated API; one database holds owner,
profile, source state, rolling article snapshots, runs, sessions and login guard.
No production host or external database has been selected or provisioned.

| Consideration | Python + SQLite, selected local | Node-based rewrite | Cloudflare Workers / Static Assets / D1 candidate |
|---|---|---|---|
| Existing workspace | Installed and tested; no dependency installation | Node available for syntax checks, but adds backend rewrite with no current requirement | Not configured/tested here; would require a runtime/storage/auth integration decision |
| Portability | Runs in existing Codespaces terminal / local Python; production needs a supported persistent process/volume | Could be evaluated later if hosting requires it | Current Python server/store is not assumed portable unchanged |
| Storage/transactions | Actual SQLite BEGIN IMMEDIATE, unique request keys and fenced source leases tested | Would need equivalent storage and transaction tests | Managed candidate's actual limits/transaction semantics not validated here |
| Authentication | Real local scrypt owner password + hashed sessions; HTTPS integration remains a release gate | Would need equivalent actual auth/security verification | No account or access policy configured; actual owner-only integration still required |
| Cost | No packages or new services added; existing Codespaces billing is not audited or guaranteed free | No demonstrated cost/benefit improvement for this slice | Free-tier eligibility, current pricing, storage/CPU/request limits must be verified before selection; no zero-cost guarantee claimed |
| Chromebook | Existing Codespaces terminal and a Private browser preview path documented | Additional setup unnecessary for this local slice | A future hosted path may be useful, but no setup/deploy is authorized |

Cloudflare remains a candidate, not an implicit selection or current pricing
recommendation. No new managed service, queue, scheduler or AI system. Choosing a
different production runtime requires a separate portability review; it is not a
reason to rewrite the working compatibility reference.

## Module and API boundaries

- [policy](../pilot/policy.py): two immutable HTTPS endpoints, policy revision 1,
  TTL 1800 seconds, synthetic retention 7200 seconds, at most 50 articles/source.
  Both live recurring-reader and live persistence flags are false. No enable flag.
- [transport](../pilot/transport.py): fixed source IDs only; explicit public DNS
  validation of all answers, vetted IP pinning, TLS hostname verification, no
  proxies, no redirect following, identity XML content type/size/truncation checks.
  An owned subprocess bounds DNS/network worker execution at 12 seconds; socket
  operations have 5-second limits. Timeout kills/waits for that owned worker.
  OS process creation/termination is not a hard realtime scheduling guarantee.
  No real network request exercised this path; hostile/slow transports are tested
  synthetically, including an actual killed sleeping worker.
- [normalize](../pilot/normalize.py): reuses the pinned bounded RSS/Atom parser
  by explicit path, without editing compatibility files. Rejects DTD/entities,
  malformed/oversized/deep XML. Display URLs must be HTTPS `brickset.com` article
  links, no userinfo/ports/backslashes; original queries preserved. Only the
  original article link is retained, not embedded offer URLs or descriptions.
  Links are never followed server-side. Missing native ID uses canonical article
  URL; no stable URL/ID evidence rejects the row, not title-based identity.
- [store](../pilot/store.py): authoritative profile, source state, runs and rolling
  snapshots, with transactional scope. No public profile selector or tenant API.
- [refresh](../pilot/refresh.py): one eligible check per enabled source, independent
  of profiles; foreground/manual only. No background thread or repeating timer.
- [auth](../pilot/auth.py), [app](../pilot/app.py): real single-owner verification,
  all data API reads/writes authenticated, mutation Origin + CSRF checks, loopback
  server and one exact browser origin. Private responses `private, no-store`.
- [static shell](../pilot/static/index.html): cache-first article view and Manage.
  Dynamic text uses DOM textContent, never HTML injection. CSRF is ephemeral;
  password clears on submit; no auth/profile/feed data in localStorage. No private
  offline service worker. Manifest present; installability/device use untested.

APIs use JSON schemaVersion 1 where applicable:

| Route | Contract |
|---|---|
| POST /api/login | Same-origin JSON password, real local hash check; HttpOnly SameSite=Strict cookie; CSRF returned only to owner session |
| GET /api/session | Auth required; owner realm and current CSRF |
| GET /api/deals | Auth required; matched retained article snapshot and mode |
| GET/PATCH /api/profile | One owner profile; full validated fields and optimistic revision; stale write 409; no fetch on edit |
| GET /api/sources | Fixed ID/market/endpoint, enabled scope, permission/mode, config revision, TTL/retention/count, success/attempt/eligibility, outcome/error/freshness/lease/validators |
| POST /api/refresh | Auth + CSRF + exact Origin; trigger open/foreground/manual and bounded Idempotency-Key; per-source run outcomes |
| POST /api/logout | Auth + CSRF + Origin; server session revoked, cookie expired, Clear-Site-Data for cache/storage; DOM cleared |

Unknown routes/query owner selectors are rejected. Body limit 16 KiB; no arbitrary
URL/config/owner field. Host checks mitigate browser DNS rebinding. No CORS grant.
HTTPS-origin mode adds Secure, host-only cookie; direct loopback HTTP is explicitly
local development only. CSP disallows inline script, third-party resources,
framing, objects and base injection. Request/body/cookie logs are disabled.

## Persistent schema v1

SQLite user_version 1. Higher/unknown versions fail closed. New-store initialization
is the only migration; no legacy compatibility cache or owner data is imported.

| Table | Contents / key |
|---|---|
| meta | Immutable synthetic or live-blocked store mode |
| owner | Exactly one owner key; random salt and scrypt verifier, no plaintext password |
| profile | Exactly one owner key, JSON schemaVersion/revision, name, enabled markets/sources, include/exclude phrases, lookbackDays, refreshPreference |
| sessions | SHA-256 session-token key, CSRF, absolute one-hour expiry; at most 8 owner sessions |
| login_guard | Persisted failed-login throttle; after 5 failures exponential lock up to 300 seconds |
| source_state | Fixed source PK, config revision, attempt/success, outcome/error, next eligibility, validators, source lease token/deadline, latest count |
| articles | Composite (source, native-ID-or-canonical-URL) PK; bounded JSON metadata, hard cache expiry index |
| runs | Run PK, unique (source, request key), trigger/config revision, start/end/outcome/error/count; latest 100 completed records retained |

Article fields include schemaVersion, sourceId/externalId/canonicalUrl, title,
market, publishedAt nullable, observedAt, firstSeenAt/lastSeenAt, cacheExpiresAt,
recordKind article, verification unverified for fixtures / reported for a future
permitted source, availability unknown, provenance, visible-field content hash and
revision. Summary and price/reference/comparison/discount/expiry/merchant/product/
promotion/restriction fields stay null. Article cache expiry is distinct from an
unknown offer expiry. Only visible retained metadata affects revision; changes
inside omitted offer tables may be missed. No product-level update claim.

## Refresh and retention behavior

BEGIN IMMEDIATE atomically reserves source lease and run identity before transport;
HTTP/parsing occur outside the DB transaction. Completion checks its exact lease
and config revision, preventing an old response overwriting a newer run. Leases
last 45 seconds, exceeding the worker boundary. Recovered expired leases are
failed with conservative backoff; old completion is fenced. Attempts timestamp
start; successful observation/last-success/end timestamp completion.

Fresh/backoff/in-flight/disabled/manual-only scopes skip without transport.
Outcomes distinguish changed, unchanged, success-empty, skipped, failed and partial.
Each accepted 200 replaces the source's rolling snapshot; disappeared articles
leave the snapshot, without implying unavailable inventory or offer expiry.
Failure preserves last-good only until original content expiry. New source failure
does not extend retention. Valid 304 needs known validators/baseline, advances
source freshness but **does not extend original content retention**. Expired
nonempty baseline cannot be reconstructed from a 304 and is failed. Synthetic
Retry-After date/numeric tests pass; source-defined longer delay is honored.

Cache expiration is independent of freshness. Purge occurs on startup/recovery and
reads/refreshes, deleting only owned cached articles/expired sessions; owner profile
and unrelated files are preserved. An idle stopped process performs no unattended
cleanup, so expired rows may remain on disk until next access/recovery; backups and
SQLite journals are not a guarantee of forensic erasure. Because **real persistent
mode is blocked**, no real source retention entitlement is assumed. Production
retention must address physical storage/backups as well as logical expiry.

Synthetic snapshot limits are an engineering test policy, not source rights.
Recurring live access, real durable rolling snapshots, provider retention duration
and repeat real retrieval remain unverified release requirements. No new budget
or source GET was used. The compatibility handoff ledger is untouched.
