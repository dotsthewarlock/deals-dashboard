### Cache/refresh remediation

- SQLite BEGIN IMMEDIATE, source-scope leases, unique source/request idempotency
  keys and config-revision fencing. One fetch per eligible source, not per profile.
  Concurrent opens cannot duplicate an active source request; a late completion
  cannot overwrite the newer lease/result.
- Attempt/start and observation/success/end clocks are separated; successful
  timestamps use completion, correcting the prototype's request-start semantics.
- Rolling snapshot replaces the previous source window, at most 50 records/source.
  Synthetic TTL is 30 minutes; synthetic retention is two hours. These are test
  policies, not rights. Cache expiry is distinct from unknown offer expiry.
- Failure preserves last-good only inside its original retention and cannot extend
  content life. Empty success, changed, unchanged, skipped, failed, partial, fresh,
  stale, unknown and expired are distinguishable. Disappearance only removes an
  item from the rolling snapshot; it does not assert unavailable stock or expiry.
- Conditional validators are used only when supplied. Synthetic supported 304
  advances source freshness without extending original content retention; a lost/
  expired nonempty baseline fails rather than inventing cached content.
- Numeric/date Retry-After and bounded exponential backoff. Expired abandoned
  leases recover as failed with conservative retry delay. Startup/read recovery
  purges owned expired articles/sessions, preserving profile and unrelated files.
- Real persistence is denied before transport, and the writer independently
  rejects non-synthetic records. Existing compatibility ledgers are untouched.

### Authentication and security

- Actual local owner password verification using random salt + scrypt. No bypass,
  default password, external auth account or JS auth token. Synthetic test-only
  passphrases are explicitly labeled and disposable. The real owner has not been
  initialized by this task; setup prompts privately via getpass.
- HttpOnly SameSite=Strict session cookie; token hash in DB; one-hour absolute
  expiry; session cap; persisted login throttling. Exact HTTPS-origin mode uses
  Secure, host-only cookies. Direct HTTP is loopback local development only.
- All owner-data API reads/writes require authentication. No caller-selectable
  tenant/owner; source/profile scope is server-side. Mutation Origin + CSRF,
  Host rebinding checks, bounded JSON bodies and strict field validation.
- No permissive CORS; CSP allows only local scripts/assets and forbids framing,
  inline script, object/base injection. DOM textContent rendering, no innerHTML.
  Responses private/no-store; request/body/cookie logging disabled.
- Logout revokes the session, expires the cookie, clears browser cache/storage
  headers and DOM. Pagehide clears private DOM before back/forward restoration;
  persisted pages reauthenticate. A failed server sign-out is not falsely reported
  as confirmed, even though the local view is cleared.
- Live transport has deny-before-DNS policy, fixed endpoints, all-answer public-IP
  validation, pinned IP + TLS hostname, no proxy or redirect follow, XML/encoding/
  size/truncation limits. An owned worker has a 12-second execution timeout and
  five-second socket phases; timeout kills/waits for it. OS spawning/termination
  is not a realtime guarantee. Tests use mocks and an actual synthetic sleeping
  worker, not a real provider or private-network request.
- Manual SQLite backup/restore only to a new private path, integrity/schema checks,
  no overwrite, restored-session invalidation and expired-state recovery. No
  actual owner backup or destructive operation was performed.
