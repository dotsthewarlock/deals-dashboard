## Implementation and preservation

- Logout clears the private DOM immediately, invalidates request generations and
  aborts old data requests. Generation checks also reject late responses when
  abort is ignored, including obsolete 401s. Only the latest cache load renders.
- Login invalidates old initial/session reads, so an old anonymous 401 cannot
  clear a successful newer login. Duplicate logins are suppressed. Logout waits
  for an already-sent login to settle and revokes its cookie; a new login cannot
  race the pending logout. Failed sign-out stays unconfirmed and offers retry.
- Profile save, entry, refresh and visibility handlers reject stale generations.
  Logout does not promise to roll back a write already accepted by the server.
- New opt-in live store uses the existing CA/US parser, normalized article model,
  transport, authenticated API and SQLite coordinator. No stack rewrite or offer
  extraction. Synthetic default and explicit live-blocked modes remain separate.
- Durable source request-attempt ledger enforces 8 attempts/source/rolling day,
  independently of the 100-entry display history and across restarts/concurrent
  claims. Existing 30-minute eligibility, leases, fencing, backoff and two-hour
  rolling retention apply. Live backup/restore is refused; explicit HTTP no-store/no-cache refuses persistence and clears the source baseline and validators. Policy revision 2
  fences old workers/validators; schema v1 adds only the attempt ledger.
- The previously missing [Gate A browser addendum](../compat/v0.0/EVIDENCE_V0.0.2_BROWSER_ADDENDUM.md)
  is included unchanged as historical evidence. Its old HOLD, dates and
  then-applicable restrictions are preserved. Original root task remains untracked
  and excluded. The three published compatibility reports and V0.1 report are
  unchanged. Current operational amendments are clearly labeled in the runbook.
